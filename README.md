# Vox

Локальная диктовка для macOS. Нажали правую `Command` — идёт запись, нажали второй
раз — распознанный текст вставляется в активное поле ввода. Речь не покидает машину:
у процесса нет разрешённой исходящей сети, аудио живёт только в памяти, история
диктовок не ведётся.

Левая `Command` работает как обычно.

## Требования

- macOS 14 или новее;
- Apple Silicon;
- Swift 6 и Xcode Command Line Tools для сборки;
- около 1.5 ГБ на диске: 483 МБ модель плюс сборка.

## Сборка

```bash
git clone https://github.com/prisonerOfMyOwnMind/vox.git
cd vox
bash scripts/fetch-model.sh
bash scripts/build-app.sh
```

Готовое приложение — `.build/Vox.app`.

## Получение и проверка модели

`scripts/fetch-model.sh` качает Parakeet TDT 0.6B v3 в формате Core ML с
HuggingFace по **закреплённой ревизии** и берёт только пять артефактов из 88 файлов
репозитория. Каждый файл сверяется по SHA-256 со списком `scripts/model-files.txt`,
лежащим в репозитории; неожиданные файлы и symlink отвергаются. Рядом с моделью
пишется `vox-model-manifest.json`.

`scripts/build-app.sh` проверяет модель до копирования в bundle и повторно после,
затем подписывает приложение и проверяет подпись. Подпись по умолчанию ad-hoc;
свой сертификат задаётся через `VOX_SIGN_IDENTITY`.

Приложение **никогда не скачивает модель** в работе. Файл пропал или изменился —
диктовка отключается с предложением переустановить проверенную сборку; чинить или
докачивать приложение не пытается.

## Установка

```bash
cp -R .build/Vox.app /Applications/
open /Applications/Vox.app
```

Иконка микрофона появится в menu bar. Окна у приложения нет.

## Разрешения macOS

Нужны три, и приложение объясняет каждое отдельно в меню:

| Разрешение | Зачем |
|---|---|
| Микрофон | запись речи |
| Мониторинг ввода | услышать правую `Command` глобально, в любом приложении |
| Универсальный доступ | отправить `Cmd+V` в активное приложение |

Это широкие разрешения, и это честная цена глобального хоткея и вставки текста:
приложение технически способно видеть факт нажатия любых клавиш. Взамен оно читает
из событий только тип, код клавиши и модификаторы, не имеет сети и ничего не пишет
на диск. Исходный код открыт — проверяйте.

Выдайте доступ в Системных настройках, затем нажмите в меню «Проверить разрешения».
Для мониторинга ввода может потребоваться перезапуск Vox.

## Как пользоваться

1. Правая `Command` — начинается запись, сверху экрана появляется тёмная капсула
   с полосами, реагирующими на голос.
2. Говорите.
3. Правая `Command` ещё раз — запись останавливается, идёт распознавание.
4. Текст вставляется в активное поле. Прежнее содержимое буфера обмена
   восстанавливается, если вы не меняли его сами во время операции.

Меню показывает текущее состояние: `starting`, `needs permissions`, `ready`,
`recording`, `transcribing`, `error`.

## Служебные режимы

```bash
.build/debug/Vox --self-test                    # проверки без интерфейса
.build/debug/Vox --transcribe-file запись.wav   # распознать файл, показать raw и normalized
.build/debug/Vox --regression fixtures/manifest.json
```

Повторяемая процедура прогона набора описана в [workflows/regression.md](workflows/regression.md).

## Удаление

```bash
rm -rf /Applications/Vox.app
```

Затем уберите Vox из трёх списков в Системных настройках, «Конфиденциальность
и безопасность». Больше приложение ничего в системе не оставляет: ни LaunchAgent,
ни login item, ни фонового процесса, ни файлов в `~/Library`.

## Приватность

- исходящая сеть запрещена на уровне процесса до инициализации приложения;
  применить не удалось — запуск прерывается;
- аудио существует только в памяти процесса и стирается после распознавания,
  независимо от исхода;
- в логи не попадают аудио, расшифровки, буфер обмена, содержимое активного
  приложения и нажатые клавиши;
- истории диктовок, аккаунтов, телеметрии, обновлятора и автозапуска нет;
- модель распознавания встроена в bundle, работает на устройстве.

## Ограничения

Честно о том, чего приложение не умеет.

- **Подтвердить вставку невозможно.** Системного способа узнать, что активное
  приложение приняло `Cmd+V`, в macOS нет. Если получатель медленный или поля ввода
  нет, текст может не вставиться, а приложение об этом не узнает.
- **Распознавание не потоковое**: текст появляется после остановки записи, а не по ходу.
- **Обработка текста намеренно тупая.** Убираются только однозначные звуки колебания,
  очевидный подряд идущий дубль и написание известных технических терминов. Смысл
  фразы не разбирается и предложения не переписываются. Словарь терминов версионирован
  и заведомо неполон.
- **Подпись ad-hoc** меняет идентичность приложения при каждой пересборке, поэтому
  macOS будет запрашивать разрешения заново. Для стабильности нужен свой сертификат.
- Только Apple Silicon, только macOS 14+.

## Как устроен репозиторий

| Путь | Что |
|---|---|
| `swift/VoxCore` | контракты и форматы результатов |
| `swift/VoxSTT` | распознавание, целостность модели |
| `swift/VoxClean` | обработка текста, WER, прогон regression |
| `swift/VoxApp` | menu bar, разрешения, хоткей, запись, индикатор, буфер |
| `scripts/` | получение модели и сборка bundle |
| `workflows/` | повторяемая процедура прогона |
| `sessions/` | дословные промпты и журнал работы |
| `fixtures/` | набор записей и ожидаемых расшифровок |

Границы между модулями и закреплённые ревизии — в [CONTRACTS.md](CONTRACTS.md).
Ход работы, замеры и отрицательные результаты — в `REPORT.md`.
