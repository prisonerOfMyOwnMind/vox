# 006 · Подпись и разрешения macOS

- Роль: главный агент
- Дата: 2026-09-03
- Симптомы владельца: «Запросить» ничего не делает; разрешение слетело после
  пересборки; иконка исчезла из menu bar; скрипт подписи упал

## Четыре разных дефекта, найденных подряд

**1. Пункт меню обещал невозможное.** «Универсальный доступ» и «Мониторинг
ввода» macOS не даёт выдать из процесса. Системный API показывает разовое окно
со ссылкой, ОДИН раз за жизнь идентичности приложения; израсходовано — молча
возвращает отказ. Исправлено: при неудаче открывается нужный список в
Системных настройках, пункт назван «Открыть настройки».

**2. Иконка пропала.** Причина — инструкция оркестратора: `rm -rf` по bundle
работающего приложения. macOS снимает иконку у процесса, чей bundle удалили,
процесс остаётся жить без интерфейса. Исправлено скриптом `scripts/install.sh`:
выход, ожидание, замена, проверка подписи, запуск.

**3. Разрешения слетают при каждой пересборке.** Подпись ad-hoc, отпечаток
меняется, macOS привязывает выданное разрешение к отпечатку. Протухшая запись
в списке дополнительно глушит повторный запрос.

**4. Скрипт постоянной подписи не работал.** Разобрано опытом, не догадкой,
на одноразовой связке ключей, которая тут же удалялась:

| Что проверялось | Результат |
|---|---|
| PKCS#12 от Homebrew OpenSSL 3.6.2 (AES-256-CBC), пустой пароль | MAC verification failed |
| PKCS#12 от `/usr/bin/openssl` (LibreSSL, устаревший формат), пустой пароль | MAC verification failed |
| PKCS#12 от Homebrew, непустой пароль | MAC verification failed |
| PKCS#12 от `/usr/bin/openssl`, непустой пароль | 1 identity imported |

То есть причин было ДВЕ сразу: формат шифрования и пустой пароль. Одну без
другой чинить бесполезно.

Дальше выяснилось третье: `security find-identity -v` самоподписанный
сертификат не показывает — он не «valid», — поэтому проверка в скрипте была бы
ложно-отрицательной даже при успешном импорте. И четвёртое: `codesign --sign`
отвечает `no identity found`, пока сертификат не помечен доверенным для подписи
кода. Это `sudo` и решение владельца.

## Что осталось решать владельцу

Постоянная подпись требует пометить самоподписанный сертификат доверенным для
подписи кода в системной связке. Это `sudo` и изменение настроек доверия.
Альтернатива — остаться на ad-hoc и выдавать три разрешения заново после каждой
пересборки. Оркестратор эти шаги не выполняет: они меняют настройки
безопасности машины.
