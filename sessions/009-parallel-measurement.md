# 009 · Замер: последовательно против параллельно

- Дата: 2026-09-03
- Материал: `regression-20260903T112345Z-clean-dict-1.json`, 7 записей
- Модель обоих прогонов: claude-opus-5, одинаковая

## Три одинаковые независимые мини-задачи

Текст задачи один и тот же в обоих прогонах, меняется только группа записей.

```
Открой файл /Users/fedorfalchuk/vox/regression-20260903T112345Z-clean-dict-1.json.
Возьми из него записи группы «<ГРУППА>».

По каждой записи группы сравни поля expected, raw и normalized и ответь:
1. что именно изменила обработка текста и помогла ли она;
2. какие технические термины модель распознала неверно и каких форм не
   хватает словарю;
3. средний WER группы до обработки и после.

Ответ — коротко, списком. Файлы не меняй.
```

Группы:
- A: записи с тегами `terms` либо только `russian`
- B: записи с тегами `filler` либо `self-correction`
- C: записи с тегами `repeat`, `enumeration` либо `injection`

## Результаты

Прогоны шли не одновременно: сначала последовательный, потом параллельный, —
иначе они мешали бы друг другу.

### Последовательный: один агент, три задачи по очереди

| | |
|---|---|
| время | **72.3 с** |
| токенов субагента | 53 611 |
| вызовов инструментов | 3 |
| возвратов в главную сессию | 1 |

### Параллельный: три агента, по задаче на каждого

| Агент | время | токенов | вызовов |
|---|---|---|---|
| группа A | 50.6 с | 51 749 | 3 |
| группа B | 49.2 с | 51 663 | 3 |
| группа C | 63.1 с | 52 742 | 3 |
| **итого** | **63.1 с по стене** | **156 154** | 9 |

### Сравнение

| | последовательно | параллельно | разница |
|---|---|---|---|
| время по стене | 72.3 с | 63.1 с | быстрее в **1.14 раза** |
| суммарно токенов | 53 611 | 156 154 | дороже в **2.9 раза** |
| возвратов в главную сессию | 1 | 3 | больше в 3 раза |

Заполнение контекста главной сессии в числах — **недоступно**: Claude Code не
показывает эту величину так, чтобы её можно было снять до и после прогона, а
измерять её по остатку бюджета нельзя — в том же окне шла посторонняя работа.
Придумывать число не стал. Косвенно измеримое: параллельный прогон вернул в
главную сессию три отчёта вместо одного, то есть контекста занял БОЛЬШЕ.

### Вывод, расходящийся с ожиданием

На трёх мелких задачах параллельность дала выигрыш по времени всего 13 % и
обошлась почти втрое дороже по токенам. Причина видна из чисел: каждый агент
тратит примерно одинаковые 52 тысячи токенов на вход в задачу, и три входа
вместо одного съедают выигрыш.

Ожидание из разбора занятия — «выигрыш параллельности в контексте главной
сессии» — на этом опыте **не воспроизвелось**, и понятно почему: там
сравнивали работу В главной сессии против делегирования субагентам. Экономию
контекста даёт само делегирование, а не параллельность. Когда делегированы оба
варианта, параллельность только умножает число возвратов.

Оговорка: три задачи по одному файлу в 7 записей — слишком мелкий материал.
На задачах, где полезная работа занимает минуты, а не секунды, соотношение
изменится в пользу параллельности.

### Побочная находка

Агент группы C заметил по существу: фикстура `dev-07` с тегом `injection`
проверяет только точность распознавания и никак не помечает, что текст внутри —
инъекция. Поля ожидаемой реакции в формате нет. Замечание верное: приложение по
контракту и не должно реагировать, оно просто распознаёт речь, — но в манифесте
это не выражено.
