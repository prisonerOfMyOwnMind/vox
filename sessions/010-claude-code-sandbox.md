# 010 · Проверка предупреждения о песочнице Claude Code

- Дата: 2026-09-03
- Версия Claude Code: 2.1.258
- Требование задания: «распространяется ли встроенная песочница Claude Code на
  terminal tools и на доступные MCP-инструменты. Используй только canary и
  запиши фактический результат»

## Ответ: предупреждение подтверждается

Официальная документация Claude Code говорит об этом прямо. Две цитаты со
страницы Sandbox environments:

> MCP servers and hooks are separate processes that run unconstrained on the host.

> The sandboxed Bash tool ... restricts only Bash commands. Built-in file tools,
> MCP servers, and hooks still run directly on your host.

То есть встроенная песочница накрывает **только инструмент Bash** и порождённые
им процессы. Мимо неё идут:

- MCP-серверы — полностью, как отдельные процессы на хосте;
- хуки — так же;
- **встроенные файловые инструменты Read, Edit и Write** — они работают через
  систему разрешений, а не через песочницу.

Последнее в разборе занятия не звучало и оказалось шире предупреждения: даже без
всякого MCP файловые инструменты самого агента песочницей не ограничены.

Источники: `code.claude.com/docs/en/sandboxing`,
`code.claude.com/docs/en/sandbox-environments`,
`code.claude.com/docs/en/settings-reference#sandbox-settings`.
Документацию читал справочный субагент; сам оркестратор страницы не открывал.

## Что измерено на этой машине

Канарейка `SANDBOX-CANARY-4KP9WD-OUTSIDE-PROJECT` в файле
`~/vox-sandbox-canary/secret.txt`, права 600, намеренно вне каталога проекта.

| Канал | Результат |
|---|---|
| Терминал, `cat` | **прочитал свободно** |
| Браузерный MCP-инструмент | открыл файл вкладкой по `file://`, но содержимое не отдал: ни текстом, ни снимком экрана |

Первый результат объясняется просто: **в этой сессии песочница не была включена
вообще**. Ключа `sandbox` нет ни в `~/.claude/settings.json`, ни в
`settings.local.json`. Поэтому ограничивать терминал было нечему, и весь день
оркестратор писал в домашний каталог, копировал приложение в `/Applications` и
удалял каталоги вне проекта.

Второй результат интереснее и уточняет предупреждение: конкретный браузерный
MCP-инструмент **имеет собственную границу по каталогу проекта** и отказался
отдавать содержимое файла снаружи. То есть «MCP идёт мимо песочницы» верно на
уровне процесса, но не означает, что каждый MCP-инструмент даёт доступ ко всему:
некоторые ограничивают себя сами.

## Как включается песочница

Отдельного флага запуска нет. Настройка в `settings.json`, корневой ключ
`sandbox`, минимально:

```
{ "sandbox": { "enabled": true, "failIfUnavailable": true } }
```

`failIfUnavailable` существенен: по умолчанию, если песочница не смогла
стартовать, Claude Code печатает предупреждение и выполняет команды **без
изоляции**. Без этого ключа песочница — не гейт, а пожелание.

Панель `/sandbox` показывает итоговую конфигурацию и режим. Признак того, что
команда ушла мимо песочницы, — заголовок промпта «Bash command (unsandboxed)»
вместо «Bash command».

## Практическое следствие для этого проекта

Если включить песочницу, часть собственных скриптов проекта сломается: на macOS
под Seatbelt блокируются Apple Events, а `scripts/install.sh` вызывает `open`,
и `dev-identity.sh` работает с связкой ключей. Их пришлось бы вносить в
`excludedCommands`, то есть выводить из-под изоляции — что для сборочных
скриптов разумно, но должно быть записано, а не сделано молча.

## Чего не сделано

Прогон с включённой песочницей не выполнялся: настройка меняет параметры
безопасности машины владельца, и оркестратор их не трогает. Документированный
ответ на вопрос задания получен и без прогона; эмпирическая проверка добавила бы
подтверждение, но не изменила бы вывод.
