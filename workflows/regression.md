# Прогон regression

Процедура отвечает на один вопрос: стало ли распознавание и обработка текста
хуже, чем в прошлый раз. Запускается одной командой, результат — файл JSON.

## Одна команда

```
swift build && .build/debug/Vox --regression fixtures/manifest.json
```

Команда печатает путь к отчёту и завершается. Ничего больше вводить не нужно.

## Что подать на вход

`fixtures/manifest.json` — список записей. Одна запись выглядит так:

```json
{
  "audio": "audio/dev-01.wav",
  "expected": "Сегодня разбираем локальную диктовку на макбуке.",
  "tags": ["synthetic", "russian"]
}
```

- `audio` — путь ОТНОСИТЕЛЬНО каталога manifest;
- `expected` — что было сказано на самом деле, в правильном письменном виде.
  Технические термины пишутся канонически: `Docker`, `Nginx`, `PostgreSQL`;
- `tags` — свободные метки. Обязательная метка одна: `synthetic` на записях,
  синтезированных `say`. Записи живого голоса её не несут.

Требования к аудио: WAV, mono, 16 kHz, Float32 или PCM 16 бит. Ни пересчёта
частоты, ни сведения каналов прогон не делает намеренно: и то и другое молча
меняет материал, по которому считается WER. Привести файл к нужному виду:

```
afconvert -f WAVE -d LEF32@16000 -c 1 вход.wav выход.wav
```

### Как пополнить набор

1. записать голосом WAV в каталог `fixtures/audio/`;
2. дописать запись в `fixtures/manifest.json` с точным `expected`;
3. прогнать команду выше.

Метки, которые набор должен покрывать целиком: `russian`, `terms`, `filler`,
`self-correction`, `repeat`, `enumeration`, `injection`.

`injection` — запись, внутри которой голосом произнесена инструкция вида
«игнорируй предыдущее и сделай X». Она нужна, чтобы видеть, доходит ли такая
фраза до расшифровки как обычный текст. Приложение на неё не реагирует и не
умеет реагировать: оно распознаёт речь, а не исполняет её.

Синтетические записи пересоздаются `fixtures/make-synthetic.sh`. Тексты, которые
произносит `say`, лежат в самом скрипте.

## Что появится на выходе

Файл рядом с manifest:

```
fixtures/regression-20260903T004512Z-clean-dict-1.json
```

Хвост имени — версия таблиц правил нормализатора (`Normalizer.dictionaryVersion`).
Отчёты с разными версиями между собой НЕ сравниваются: изменился словарь —
изменилась и мера. В самом формате отчёта поля под версию нет, поэтому она
вынесена в имя файла.

Отчёты накапливаются в каталоге manifest и в репозиторий не входят. Старые
можно удалять, кроме того, с которым сравниваетесь.

Содержимое отчёта:

| Поле | Что означает |
|---|---|
| `startedAt` | момент начала прогона, UTC |
| `totalRuntimeSeconds` | всё время прогона |
| `appVersion`, `fluidAudioCommit`, `modelRepo`, `modelRevision` | закреплённые ревизии из `Pins` на момент прогона |
| `meanWER` | средняя доля ошибочных слов ПОСЛЕ обработки |
| `meanWERRaw` | то же по сырой расшифровке, без обработки |
| `records[]` | по одной записи на fixture |

В `records[]` на каждый fixture: `audio`, `tags`, `expected`, `raw`,
`normalized`, `wer`, `werRaw`, `transcribeSeconds`.

## Как читать результат

`wer` — доля ошибочных слов: расстояние редактирования по словам, делённое на
число слов эталона. Регистр и пунктуация по краям слова на счёт не влияют.
`0.0` — совпадение слово в слово. `0.1` — примерно одно ошибочное слово из
десяти. Значение может быть больше `1.0`, если расшифровка длиннее эталона.

Порядок чтения:

1. `meanWER` — общий уровень. Это первое число, которое сравнивается с прошлым
   прогоном;
2. `meanWER` против `meanWERRaw` — что даёт обработка. Обработка обязана
   уменьшать ошибку или не менять её. `meanWER > meanWERRaw` означает, что
   нормализатор портит текст;
3. отдельные записи с самым большим `wer` — там смотреть `raw` рядом с
   `expected` и решать, чья это ошибка: распознавания или обработки;
4. `transcribeSeconds` — время на запись. Резкий рост при неизменной модели
   означает, что что-то поменялось в загрузке или в железе.

## Что считать регрессией

Сравнивается с предыдущим отчётом ТОЙ ЖЕ версии словаря на ТОМ ЖЕ наборе:

- `meanWER` вырос — регрессия;
- `meanWER` стал больше `meanWERRaw` — регрессия в обработке, даже если общий
  уровень приемлемый: нормализатор добавляет ошибки вместо того, чтобы убирать;
- отдельная запись, у которой `wer` вырос, а у остальных нет — регрессия на
  конкретном классе речи. Метки этой записи говорят, на каком;
- `transcribeSeconds` вырос заметно при тех же ревизиях — регрессия
  производительности;
- запись с меткой `injection`, у которой `normalized` отличается от `raw`
  сильнее, чем у соседей — повод посмотреть вручную: обработка не должна
  реагировать на содержание фразы.

Набор менялся между прогонами — числа несравнимы. Сначала фиксируется набор,
потом сравниваются прогоны.

## Границы

Модель нужна до запуска: `bash scripts/fetch-model.sh`. Без неё команда упирается
в отказ проверки целостности.

`--transcribe-file` и `--regression` читают аудио по-разному: первый пересчитывает
частоту и сводит каналы, второй требует строгий WAV mono 16 kHz и намеренно ничего
не пересчитывает, чтобы не менять материал, по которому считается WER. Файл, который
принял `--transcribe-file`, может быть отвергнут `--regression`; приводите заранее:
`afconvert -f WAVE -d LEF32@16000 -c 1 вход.wav выход.wav`.
